# Conventions

> Generated by Sauron from the discovery interview. Treat as the source of truth for this project.

- New DSP/neural stage logic lives in app/core/ (e.g. app/core/humanizer.py), following the existing module-per-stage pattern used by vocal_chain.py, remix_master.py, qa_gate.py
- Cache humanizer output under cache/<track_id>/stems/ using the existing NEURAL_FILENAME_PREFIX-style naming + settings-hash convention already used in vocal_chain.py/neural_common.py
- New UI controls go in app/ui/vocal_panel.py and app/ui/ab_compare_view.py, matching existing slider/control patterns already present in those files
- All new constants (drift depth/rate ranges, breath blend gain, QA metric thresholds) are named module-level constants at the top of their owning file, mirroring vocal_chain.py's HPF_CUTOFF_HZ/NOTCH_* style
- New settings fields go in app/models/settings.py and app/models/preset.py alongside existing denoise/enhance intensity fields
- Binary/model downloads follow the existing app/setup/model_downloader.py + setup_wizard.py pattern — no ad hoc download logic elsewhere
- Standard test coverage: new pytest tests under tests/ mirroring existing test file naming for each new module/function
- No new top-level dependencies beyond pyrubberband; the rubberband binary is fetched at setup time, not pip-installed
